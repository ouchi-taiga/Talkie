# 要件定義書：チャット小説メーカー (Talkie)

最終更新: 2026-08-04

この文書は「何を作るか」を扱う。「どう作るか」は [design.md](design.md) を参照。

---

## 1. プロジェクトの目的

LINE 風のチャット画面を作成し、リアルタイムプレビュー・PNG 書き出し・1発言ずつの
アニメーション再生を行う Web アプリ。

このプロジェクトには目的が2つある。優先順位は同列。

1. **サービスを一から作り上げる経験を得る。** フロントだけでなくバックエンド・DB・
   認証・デプロイまで自分で通す。
2. **実際に使える成果物を作る。** 自分が SNS 投稿用のチャット画像を作るのに使う。

### 学習対象として明示的に含めるもの

- DB 設計・リレーション設計
- API 設計 (SvelteKit のサーバーサイド)
- 認証・認可
- インフラ・デプロイ (Vercel, CI/CD)

### 方針

- **既存ライブラリは積極的に使う。** 車輪の再発明はしない。生 SQL を書く必要はなく、
  ORM を使う。認証も既製ライブラリを使う。ただし「何をしているか説明できる」状態を保つ。
- **拡張性・可用性を持たせた設計にする。** 具体的な方針は [design.md](design.md) §5 を参照。

### 想定ユーザー

- SNS (TikTok, Instagram, X) にチャット風の画像を投稿したい人
- 当面は自分が使う

| 機能                                | 外す理由                                             |

| 課金・マネタイズ                    | まず需要を確認する。方針は §7 に記載                 |

## 3. 機能要件

### 3.1 認証

- メールアドレスとパスワードでサインアップ・ログインできる
- ログアウトできる
- **他人の作品にアクセスできない**
- 未ログインでもお試し利用はできる (§3.2)。ただし保存された作品にはアクセスできない

### 3.2 お試し利用 (未ログイン)

ログインを必須にすると利用の障壁になるため、**登録なしで試せるようにする**。

- 未ログインでも作成・編集・プレビュー・書き出しができる
- **保存はされない。** データはブラウザ内 (localStorage) に一時的に置くだけ
- **「保存されません」と明示する。** ブラウザやOSがデータを消すことがあるため
  (iOS では数週間の未使用でストレージが消去されることがある)
- **作ったら書き出しを促す導線を置く。** 消える前に成果物を持ち帰らせる
- 保存したい場合は登録に誘導する
- **お試しで作ったデータを登録後に引き継ぐ処理は作らない** (スコープ外)

### 3.3 作品管理

- 作品を新規作成できる
- 自分の作品を一覧できる (更新日時の新しい順)
- 作品のタイトルを変更できる (管理用の名前。チャット画面には出ない)
- **チャット画面のヘッダーに出す名前**を設定できる (相手の名前やグループ名)
- **グループの人数**を設定できる。設定しなければ1対1として扱う
- 作品を削除できる (含まれるキャラクター・発言も一緒に消える)

### 3.4 キャラクター管理

- 作品ごとにキャラクターを追加・編集・削除できる
- 設定できる項目:
  - 名前
  - 吹き出しの色
  - アイコン画像 (任意)
  - **自分 / 相手** の区分 — プレビューでの左右の配置が変わる

### 3.5 見た目 (チャット画面のデザイン)

複数のメッセージアプリ風のデザインを選べるようにする。
**レイアウトと配色を別々に選べる。**

| 軸             | 内容                                                     |
| -------------- | -------------------------------------------------------- |
| **レイアウト** | 画面の構造。ヘッダーや入力欄に並ぶアイコン、吹き出しの形 |
| **配色**       | 色。将来は壁紙やフォントも含める (着せ替え)              |

- 作品作成時にレイアウトと配色を選ぶ
- **後からいつでも変更できる。** どちらも作品の属性として保持する
  (作った後に別のデザインで書き出したくなるため)
- 組み合わせて使える (レイアウトA × 緑、レイアウトA × 青、レイアウトB × 緑 …)
- **チャット画面のヘッダーと入力欄も再現する。** 書き出し時に含めるかは選べる
- **グループのときだけ相手の名前を吹き出しの上に出す。** 1対1では出さない

**重要な制約 — 実在サービスの商標・ロゴを使わない:**

- **ロゴ・アイコン画像をアプリに同梱しない。** アイコンはユーザーがアップロードする
- **レイアウト名・配色名に実在サービス名を使わない。** 「グリーン」「ブルー」等の中立な名前にする
- UI 上・説明文上でも実在サービス名を使わない
- 理由と背景は [design.md](design.md) §7 を参照

### 3.6 チャットエディタ

**トーク画面の上で直接編集する。** 編集用の画面とプレビュー画面を分けない。
見ている画面がそのまま編集対象であり、書き出される絵でもある。

#### 2つのモード

| モード         | 表示                                                           |
| -------------- | -------------------------------------------------------------- |
| **編集モード** | ドラッグ用のつまみ、追加用の点線の吹き出し、選択中の枠線を出す |
| **プレビュー** | 編集用の要素をすべて隠す。**書き出される絵と同じ状態**         |

- いつでも切り替えられる
- **書き出しはプレビューの状態で行う。** 編集用の要素が写り込まないようにする

#### 操作

| 操作                         | 結果                                            |
| ---------------------------- | ----------------------------------------------- |
| 吹き出しをタップ             | **その場で本文を編集できる** (画面遷移しない)   |
| 吹き出しを長押し             | 操作メニューが出る (既読・時刻・削除・話者変更) |
| つまみを**縦にドラッグ**     | 並べ替え                                        |
| つまみを**横にドラッグ**     | **話者の変更** (左に出すと相手、右に出すと自分) |
| 末尾の点線の吹き出しをタップ | 種別を選んで発言を追加                          |

- **ドラッグはマウスとタッチの両方で動くこと。** 上下ボタンでの代替は行わない
- **長押しで操作メニューを出す。** タップを編集に使うため、また画面のスクロールと
  誤操作しないようにするため
- 発言タイプを選べる:

| タイプ             | 内容                                                   |
| ------------------ | ------------------------------------------------------ |
| テキスト           | 話者を選んで本文を入力。自分/相手の区分で左右が決まる  |
| 画像添付           | 画像をアップロードして表示                             |
| システムメッセージ | 「〇〇が退室しました」等。中央に表示され話者を持たない |
| **日付ラベル**     | 「今日」「1月1日(月)」等、会話の区切りに中央へ表示する |

- システムメッセージと日付ラベルは**話者を持たないため、横のドラッグの対象外**。
  並べ替え (縦) はできる
- 各発言に **既読表示** のオン/オフを設定できる
- 各発言に **時刻** を設定できる (「12:34」等)。吹き出しの脇に表示される。
  実際の時刻ではなく創作物の演出なので、任意の文字列を入れられる
- **編集した内容が即座に画面へ反映される** (保存を待たない)

### 3.7 PNG 書き出し

- 書き出し形式を選べる:

| 形式               | 内容                                                            |
| ------------------ | --------------------------------------------------------------- |
| 長尺1枚            | チャット画面全体を縦長の1枚にする                               |
| **画面サイズ単位** | スマホ画面1枚ずつに分割した複数枚。SNS に連続投稿する用途に向く |

- **ヘッダーと入力欄を含めるかを選べる**

- 日本語が正しく描画されること
- **iOS で画像を端末に保存できること。** 実現方法は [design.md](design.md) §6.4 を参照

### 3.8 再生モード

- 画面をタップするごとに1発言ずつ順に表示される
- 最初から再生し直せる

### 3.9 設定

- **ダークモード切替** (ライト / ダーク / OS設定に従う)
- **言語設定** (§3.10)
- ユーザー設定の変更 (表示名など)
- ログアウト

### 3.10 多言語対応

- **日本語・英語**に対応する。初期表示はブラウザの言語設定から判定する
- 設定画面から切り替えられる
- **未ログインでも切り替えられる** (お試し利用でも効く)
- **後から言語を追加できる設計にする。** 3言語目を足すときに、UI のコードを
  書き換えなくて済むようにする
- **UI の文字列をコードに直接書かない。** 翻訳ファイルにまとめる

実現方法は [design.md](design.md) §6.8 を参照。

## 4. 非機能要件

| 項目                 | 要件                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------- |
| **レスポンシブ対応** | **PC・タブレット・スマホすべてで使えること。必須要件とする**                                |
| 編集の応答性         | 入力した内容が遅延なく画面へ反映されること。DB 保存を待たない                               |
| データ永続性         | ログイン時は DB に保存し、デバイスを変えても引き継げること。未ログイン時は保存しない (§3.2) |
| 保存タイミング       | 自動保存。編集のたびにサーバーへ送るのではなく、一定間隔または操作単位でまとめる            |
| **PWA**              | ホーム画面に追加してアプリのように起動できること                                            |
| 運用コスト           | 無料枠内で運用する (Vercel Hobby + Supabase Free)                                           |
| 認可                 | 他人の作品にアクセスできないこと                                                            |
| 秘匿情報             | DB 接続情報・API キーはサーバーサイドのみで扱い、ブラウザに露出させない                     |
| 商標                 | 実在サービスのロゴ・名称を使わないこと (§3.5)                                               |
| **多言語**           | UI の文字列をコードに直接書かず、言語を後から追加できること (§3.10)                         |
| 並べ替え操作         | **マウスとタッチの両方でドラッグ＆ドロップできること** (上下ボタンでの代替は不可)           |

### 4.1 レスポンシブの方針

**トーク画面はどの画面幅でも常に見えている。** 編集用の画面を別に持たない (§3.6)。
変わるのは作品設定の置き場所だけ。

| 画面幅                    | 作品設定の置き場所                           |
| ------------------------- | -------------------------------------------- |
| PC (広い)                 | **画面左のパネルに常時表示**。右がトーク画面 |
| タブレット・スマホ (狭い) | **オーバーレイ**。トーク画面の上に重ねて出す |

- **判定は画面幅で行う。** タッチデバイスかどうかでは判定しない。
  サイドパネルを置けるかは幅の問題であり、また「タッチとマウスの両方が使える」
  端末 (タッチ対応ラップトップ、キーボード付きタブレット) が普及しているため
  入力方法での二分は成立しない
- タッチ操作への配慮は**操作対象を大きくすること**で行う (小さくはしない)

## 6. 画面一覧

レイアウトの詳細は [design.md](design.md) §6 を参照。

| パス                  | 画面                                | 認証     |
| --------------------- | ----------------------------------- | -------- |
| `/`                   | ランディング                        | 不要     |
| `/try`                | **お試しエディタ** (保存なし、§3.2) | **不要** |
| `/login`, `/signup`   | ログイン・サインアップ              | 不要     |
| `/projects`           | 作品一覧                            | 必要     |
| `/projects/new`       | 新規作成 (レイアウト・配色を選ぶ)   | 必要     |
| `/projects/[id]`      | エディタ (メイン画面)               | 必要     |
| `/projects/[id]/play` | 再生モード                          | 必要     |
| `/settings`           | 設定 (ダークモード等)               | 必要     |

### 6.1 利用の流れ

```text
ランディング
  ├─ 「まず試す」 → /try           保存なし。書き出しは可能。登録に誘導
  └─ ログイン    → /projects      作品一覧
                      ├─ 新規作成 → レイアウト・配色を選ぶ → エディタ
                      └─ 既存を開く → エディタ

エディタ = トーク画面そのもの
  作品設定 (PC: 左パネル / スマホ: オーバーレイ)
  トーク画面の上で直接編集
    吹き出しをタップ  → 本文を編集
    吹き出しを長押し  → 既読・時刻・削除・話者変更
    つまみを縦にドラッグ → 並べ替え
    つまみを横にドラッグ → 話者の変更
    末尾の点線をタップ → 発言を追加 (種別を選ぶ)
  └─ プレビュー (編集用の要素を隠す)
       └─ 書き出し → 長尺1枚 or 画面サイズ単位で複数枚
  └─ 再生モード
```

## 7. マネタイズの方針 (将来)

MVP には含めない。まず需要を確認する。方針だけ記録しておく。

### 7.1 前提として分かっていること

- **Web の直接課金の方が手数料が安い。** Apple の IAP は 15〜26%、Web (Stripe/KOMOJU) は
  3.25〜3.6%。日本ではスマホ新法 (2025-12-18 施行) によりアプリから外部 Web 決済へ
  リンクできるため、アプリ化しても IAP を使う必要はない
- **デジタルコンテンツは料率が別建てで高い。** PayPay はオンライン物販 3.8% に対し
  デジタルコンテンツ **約9.5%**、キャリア決済は **15%**。カード決済は影響を受けない
- **キャリア決済は継続課金 (サブスク) に使えない。** 都度課金のみ
- **フリーミアムの転換率は 2〜5% が標準**

### 7.2 想定する方向性

- **カード情報の入力は心理的障壁が高い。** 無名の個人開発アプリでは特に。
  **PayPay 等の外部決済の方が抵抗が少ない** (ユーザーはアプリ内で承認するだけ)
- したがって **都度課金 (クレジットパック等) から検討する。** サブスクは後
- 課金対象として考えられるもの: 書き出し時のウォーターマーク除去、高解像度書き出し、
  テーマの追加、キャラクター数の上限解放
- 決済事業者の候補: **KOMOJU** (カード 3.25%、月額固定費なし、日本の決済手段が揃う)、
  Stripe (3.6% + サブスクは Billing +0.7%、キャリア決済なし)

### 7.3 課金の前に必要なこと

- **商標リスクの解消 (§3.5)。** 無料の個人ツールと、収益を得るツールではリスクの
  評価が変わる。ロゴ・名称を使わない設計を徹底する
- **知財に詳しい弁護士への相談**
- 特定商取引法の表示義務 (氏名・住所・電話番号)。個人事業主も免除されない

### 7.4 アプリ化 (App Store / Google Play)

- **無料アプリでも Apple Developer Program の年額 99 USD が必要。** 免除は米国の
  非営利・教育機関のみで、個人事業主は対象外
- Google Play は 25 USD の一回払いのみ
- **まず PWA で公開し、需要が確認できてからアプリ化を判断する**
